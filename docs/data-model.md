# Data model (Convex)

Source of truth: `convex/schema.ts`. Every public function calls `requireUser`
(signed in and on the sign-up allowlist). Campaign data is reached through
`loadCampaign` (`convex/lib/access.ts`), which returns the caller's role: the
campaign's creator (`ownerId`) is its **GM**; a `campaignMembers` row or a
`campaignInvites` row for the caller's email makes them a **player**. Players
read what the decisions in `docs/decisions-d3-d11.md` allow; writes to campaign
state are GM-only unless a later phase says otherwise.

| Table | Fields | Indexes | Notes |
|---|---|---|---|
| `campaigns` | `ownerId`, `frameId` (published frame id or `custom`), `name`, `nameKey`, `tier`, `level`, `custom?` (`pitch`, `tones`, `themes`, `touchstones`, `partySize`, `startingTier`, `background`), `createdAt`, `lastOpenedAt` (the GM's), `deletedAt?`, `joinCode?`, `options?` (optional-rule switches; unset = frame default, see `src/lib/frames/options.ts`), `tome?` (custom frames: `{overview, incident, mechanics}`) | `by_owner_lastOpened`, `by_owner_nameKey`, `by_joinCode` | `nameKey = name.trim().toLowerCase()`; names are unique per GM among campaigns that are not deleted. Delete sets `deletedAt` (undo clears it); nothing is hard-deleted. JS `trim`/`toLowerCase` are slightly stricter than the old Postgres `btrim`/`lower`. |
| `campaignMembers` | `campaignId`, `userId`, `joinedAt`, `lastOpenedAt` | `by_campaign`, `by_user`, `by_campaign_user` | Players. Created by `members.joinByCode`, or when an invited player first opens the campaign (`campaigns.markOpened`). The GM has no row. |
| `campaignInvites` | `campaignId`, `email` (normalised), `invitedBy`, `createdAt` | `by_campaign`, `by_email`, `by_campaign_email` | Email invites; an invite counts as membership for the account with that email. Removing a player deletes their member row and invites. |
| `campaignState` | `campaignId`, `fear` | `by_campaign` | Created with Fear 0 in the same transaction as the campaign. `fear.adjust` (±1) and `fear.set` (0–12) change it; both are idempotent. Fear is core. |
| `countdowns` | `campaignId`, `name`, `description`, `category` (threat/project/consequence/other), `startingValue` (1–20), `currentValue`, `status` (active/paused/completed/cancelled), `consequence`, `completedAt?`, `createdAt` | `by_campaign` | Legacy rules (`applyCountdownAction`): advance/reverse ±1 (blocked while paused), correction by any amount (allowed while paused), 0 completes, a completed countdown reopens only upward, cancelled is final and hidden. `completedAt` is set once per active lifecycle and cleared on reopen. **No event history** (user decision 2026-10-17). Countdowns are core. Frame trackers may own countdowns (`ownerKey`, e.g. `nation:armada`; `kind`, e.g. `objective-major`; `revealed`); those are left out of the dashboard list and are GM-only until revealed. |
| `campaignTime` | `campaignId`, `week` (≥1), `cycle` (DAY/NIGHT), `cycleDay` (1–7) | `by_campaign` | Witherwild only (frames with `campaignTime`); created with the campaign at week 1 / DAY / 1. Month = ⌊(week−1)/4⌋+1 and the phase name are derived, never stored. `advance` moves one day (after day 7: week+1, other cycle); `setDay` sets a day in the current week and must change it. Every function throws `MECHANIC_DISABLED` for other frames. |
| `characters` | `campaignId`, `ownerId`, `createdBy`, `status` (active/dead/retired), `sheet` (any; validated by `characterSheetSchema` in `src/lib/validation/characters.ts`), `createdAt`, `updatedAt` | `by_campaign`, `by_owner` | Player characters. Everyone in the campaign reads every sheet; the owner (a player, or the GM for an unassigned character) and the GM edit. Created from the 9-step wizard (`characters.create` derives starting values from the class: Evasion, HP, Stress 6, Hope 2, Proficiency 1, two Experiences at +2, two level-1 domain cards, a handful of gold). `sheet.evasion` is the base; equipment modifiers are derived (`derivedDefense`). Portraits: design art ids or Convex file storage uploads (old uploads deleted when replaced). |
| `frameTrackers` | `campaignId`, `key`, `data` (any), `updatedAt` | `by_campaign_key` | One row per campaign and frame tracker; each module in `convex/trackers/` validates `data` with zod (`src/lib/frames/trackers/*`) and filters it for players. Keys: `fiveBanners.state`, `colossus`, `ageOfUmbra`, `weredragon`, `andaluria`, `horizon`; character extras `character:<id>:{beastform,companion,motherboard,beastFeast,castleHigh}` and `beastFeast.cookbook` (`convex/characterExtras.ts`). |
| `codexEntries` | `campaignId`, `kind` (character/location), `data` (any; validated by `codexEntryDataSchema` in `src/lib/codex/schema.ts`: `name` ≤120, `role` ≤160, `known`, `pdesc` ≤8000, `gmn` ≤8000, `images` ≤8 `{storageId, shown}`, `cover`, `allegiance`, `allegianceShown`, `region`, `tokenId`), `createdAt`, `updatedAt` | `by_campaign_kind` | Characters & Locations (`convex/codex.ts`), ≤500 per campaign. GM-only writes. `codex.list` sends players only `known` entries with `name`, `pdesc`, the shown allegiance, the region, revealed images (URLs resolved only for those) and `tokenId` only when the linked World map token exists and isn't hidden; `role`, `gmn`, the true allegiance and hidden images never leave the server. Allegiances and regions come from the frame (`factionsFor`/`regionsFor`); a location's region follows its pin on the Witherwild map. The frame's starting characters are seeded once per campaign (`codex.seed`, idempotency key `codex:seed`). |
| `codexImages` | `storageId`, `campaignId`, `entryId`, `uploadedBy`, `createdAt` | `by_storage`, `by_entry` | Ownership of codex image files: `attachImage` accepts only an unclaimed (also not a portrait) image ≤ 3 MB and records it here; only an entry's own files are deleted (on image removal or entry deletion). A rejected file is deleted and the reason returned instead of thrown. |
| `maps` | `campaignId`, `data` (any; validated by `mapStateSchema` in `src/lib/world/map-state.ts`), `updatedAt` | `by_campaign` | The World map (`convex/maps.ts`), one row per campaign, written on first change (until then the frame's initial state: Witherwild gets the board's suggested terrain). `data`: `tokens` ≤500 `{id, type, x, y (map %), name ≤80, notes ≤2000, hidden, location}`, `nextId`, `party {x, y, trail ≤12}`, `terrain` (128 × 98 chars of `rwdmh.#`), `scaleKm`, `options {method, pace, hours, units, trail, rules?}` (`rules` = GM overrides of the house-rule speeds), `customTypes` ≤40, `typeLabels`, `customMap? {storageId, width, height}`, `hexCrawl?` (Journey to Horizon: `grid {originX, originY, size px, orientation}`, `hexes` ≤4000 `{q, r, explored, terrain?, habitat?, region?, poi? {text, hidden}}`, `party {q,r}|null`, `day`, `travelMode`, `lastMove?`). Stored JSON ≤ 800 000 chars. GM-only writes; players get `playerMapView`: hidden tokens removed, notes blanked, and of the hex crawl only explored hexes plus the party's hex and its neighbours, without hidden POIs or `lastMove`. |
| `mapUploads` | `storageId`, `campaignId`, `uploadedBy`, `createdAt` | `by_storage`, `by_campaign` | Ownership of uploaded map images: `attachMapImage` accepts only an unclaimed image ≤ 8 MB (a rejected file is deleted and the reason returned, not thrown), deletes the campaign's previous upload; the URL is resolved only for a file recorded for the same campaign. |
| `settings` | `ownerId`, `tableName`, `gmName`, `accent` | `by_owner` | One row per GM, created on first save. `accent` is one of the four palette colours. |
| `operations` | `scopeKey`, `idempotencyKey`, `kind`, `requestHash`, `result`, `campaignId?`, `createdBy`, `createdAt` | `by_scope_key`, `by_campaign` | Idempotency records (`convex/lib/operations.ts`). A replay with the same kind and normalised request returns `result`; anything else with the same key is `IDEMPOTENCY_MISMATCH`. Campaign create uses scope `owner:<id>`; Fear, countdown create and campaign time use `campaign:<id>`; countdown operations use `countdown:<id>`. With no event tables, these records are also the trail of applied changes. |

Convex Auth's `authTables` are included unchanged.
