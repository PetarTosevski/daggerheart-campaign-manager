# Data model (Convex)

Source of truth: `convex/schema.ts`. Every public function calls `requireUser`
(signed in and on the sign-up allowlist). Campaign data is reached through
`loadCampaign` (`convex/lib/access.ts`), which returns the caller's role
(maps, codex and characters check access through `permissionFor` in
`convex/lib/permissions.ts`, which starts from the same role; see `grants`): the
campaign's creator (`ownerId`) is its **GM**; a `campaignMembers` row or a
`campaignInvites` row for the caller's email makes them a **player**. Players
read what the decisions in `docs/decisions-d3-d11.md` allow; writes to campaign
state are GM-only unless a later phase says otherwise.

| Table | Fields | Indexes | Notes |
|---|---|---|---|
| `campaigns` | `ownerId`, `frameId` (published frame id or `custom`), `name`, `nameKey`, `tier`, `level`, `custom?` (`pitch`, `tones`, `themes`, `touchstones`, `partySize`, `startingTier`, `background`), `createdAt`, `lastOpenedAt` (legacy fallback only, no longer written), `deletedAt?`, `joinCode?` (set at creation), `options?` (optional-rule switches; unset = frame default, see `src/lib/frames/options.ts`), `tome?` (custom frames: `{overview, incident, mechanics}`) | `by_owner_deletedAt_lastOpened`, `by_owner_deletedAt_nameKey`, `by_joinCode`, `by_deletedAt` | `nameKey = name.trim().toLowerCase()`; names are unique per GM among campaigns that are not deleted. Delete sets `deletedAt` (undo clears it). Nothing is hard-deleted automatically: `internal.cleanup.purgeCampaign` can remove a campaign with all its rows, grants and files (tested to cover every campaign-scoped table), but no cron schedules it until a GM "Delete permanently" action exists. JS `trim`/`toLowerCase` are slightly stricter than the old Postgres `btrim`/`lower`. |
| `campaignOpens` | `userId`, `campaignId`, `lastOpenedAt` | `by_user_campaign`, `by_user_lastOpened` | When each user last opened each campaign, for list order. `campaigns.markOpened` writes it at most every 5 minutes and never patches `campaigns`, so opening a campaign doesn't re-run every player's queries. |
| `history` | `campaignId`, `kind` (`fear` / `countdown` / `campaignTime`), `action`, `by` (user or null), `at`, `before`, `after` (typed per kind), `countdownId?` | `by_campaign_at` | One row per Fear, countdown or campaign-time change (including `gainFear` from frame trackers). GM-only, newest first via `history.list` (paginated). Kept when `operations` expires. |
| `actionLog` | `campaignId`, `characterId?`, `actorId`, `kind`, `visibility` (public / gm), `summary`, `roll?`, `groupId?`, `before?` (stored sheet snapshot), `fearDelta?`, `undoable`, `undoneAt?`, `at` | `by_campaign_at`, `by_campaign_visibility_at`, `by_character_at`, `by_campaign_group` | D5 roll feed and undo. Players see public rows; GM free rolls stay GM-only unless revealed. Undo restores the group's oldest snapshot per character and reverts its Fear; any newer row on that character blocks it (`UNDO_STALE`). |
| `rests` / `restChoices` | rest: `campaignId`, `kind` (short/long), `status`, `startedBy`, timestamps; choice: `restId`, `characterId`, `moves` | rests: `by_campaign_status_started`, `by_campaign_started`; restChoices: `by_rest_character`, `by_campaign` | D5 GM-run party rests: the GM opens a rest, each player picks two moves, the GM finishes it. The short-rest count comes from the rests index. |
| `campaignMembers` | `campaignId`, `userId`, `joinedAt`, `lastOpenedAt` (legacy fallback only) | `by_user`, `by_campaign_user` | Players. Created by `members.joinByCode`, or when an invited player first opens the campaign (`campaigns.markOpened`). The GM has no row. |
| `campaignInvites` | `campaignId`, `email` (normalised), `invitedBy`, `createdAt` | `by_email`, `by_campaign_email` | Email invites; an invite counts as membership for the account with that email. Removing a player deletes their member row and invites. |
| `campaignState` | `campaignId`, `fear`, `sessionStartedAt?`, `extraCharactersSession?` | `by_campaign` | Created with Fear 0 in the same transaction as the campaign. `fear.adjust` (±1) and `fear.set` (0–12) change it; both are idempotent. Fear is core. `sessionStartedAt` marks the running session (`sessions.start`/`end`). `extraCharactersSession` (XC1) holds the `sessionStartedAt` of the session in which the GM allows more than one active character per player (`sessions.allowExtraCharacters`); it applies only while it equals `sessionStartedAt`, and `sessions.start`/`end` clear it. |
| `countdowns` | `campaignId`, `name`, `description`, `category` (threat/project/consequence/other), `startingValue` (1–20), `currentValue`, `status` (active/paused/completed/cancelled), `consequence`, `completedAt?`, `createdAt`, `ownerKey?`, `kind?`, `revealed?`, `visibility?` (`{ mode: "private" }` or `{ mode: "public", hidden: ("name"|"description"|"category"|"consequence"|"progress")[] }`) | `by_campaign_owner` | Legacy rules (`applyCountdownAction`): advance/reverse ±1 (blocked while paused), correction by any amount (allowed while paused), 0 completes, a completed countdown reopens only upward, cancelled is final and hidden. `completedAt` is set once per active lifecycle and cleared on reopen. Changes are recorded in `history` (user decision 2026-10-18). Countdowns are core. Frame trackers may own countdowns (`ownerKey`, e.g. `nation:armada`; `kind`, e.g. `objective-major`; `revealed`); those are left out of the dashboard list and are GM-only until revealed. Dashboard countdowns carry `visibility` (CV1, widened 2026-10-19; absent = everything public): `countdowns.listByCampaign` drops private countdowns for players and returns hidden fields as `null` (hidden progress blanks `currentValue` and `startingValue`, the status stays); the GM sets it on `create` and changes it with `countdowns.setVisibility`. |
| `campaignTime` | `campaignId`, `week` (≥1), `cycle` (DAY/NIGHT), `cycleDay` (1–7) | `by_campaign` | Witherwild only (frames with `campaignTime`); created with the campaign at week 1 / DAY / 1. Month = ⌊(week−1)/4⌋+1 and the phase name are derived, never stored. `advance` moves one day (after day 7: week+1, other cycle); `setDay` sets a day in the current week and must change it. Every function throws `MECHANIC_DISABLED` for other frames. |
| `characters` | `campaignId`, `ownerId`, `createdBy`, `status` (active/dead/retired/away), `away?` (`{ reason: infirmary/sentHome/benched, note?, requested? }`), `deathMoveSpent?` (`true`), `sheet` (any; validated by `characterSheetSchema` in `src/lib/validation/characters.ts`), `createdAt`, `updatedAt` | `by_campaign`, `by_owner` | Player characters. Everyone in the campaign reads every sheet; the owner (a player, or the GM for an unassigned character) and the GM edit. Created from the 9-step wizard (`characters.create` derives starting values from the class: Evasion, HP, Stress 6, Hope 2, Proficiency 1, two Experiences at +2, two level-1 domain cards, a handful of gold; in Motherboard no gold and a Network tether in the inventory instead, with 5 quantum in the Ikonis module, CB 301-302, RF4). `migrations/motherboardEconomy:addTetherAndQuantum` (RF4) gives older Motherboard characters the tether and, when they have no Ikonis module row yet, one with the starting 5 quantum; it leaves existing gold and quantum alone. Features that grant a slot (Vengeance At Ease, School of War Battlemage, Giant Endurance, Human High Stamina, including a mixed ancestry's pick; table `FEATURE_SLOTS` in `src/lib/domain/characters/slots.ts`) raise `hpMax`/`stressMax` at creation or with the multiclass level-up (undo takes it back); `sheet.slotBonuses` (optional string array of applied keys, SS1) keeps each from being applied twice (views carry it since SS2). `sheet.multiclass.spellcastTrait` (optional trait id, widened, SS2, CB 111): the Spellcast trait chosen when multiclassing into a subclass with one (asked only when both subclasses have different traits; forced to the new one without an original); `spellcastTraitOf` (`src/lib/domain/characters/spellcast.ts`) gives the effective trait (choice, else the original, else the multiclass) for magic weapons, Warlock/Witch/Seraph features and the sheet. `sheet.advancements[].at` (optional ms timestamp, widened, SS3): when the level-up was taken; a player may undo it only while no session started or ended since (`levelUp.undoLast`, `levelUp.canUndo`), older entries without it are GM-only. `migrations/slotBonuses:applySlotBonuses` backfills existing sheets (photo imports only record the keys, since their maximums came from the paper sheet). `sheet.evasion` is the base; equipment modifiers are derived (`derivedDefense`). `away.requested` (optional `true`, widened, LL1): a player's Castle High less-lethal death move picked the reason and the GM has not settled it (`deathMoves.settleAway` confirms or changes it and drops the flag); absent means final, so older rows stay settled; `deathMoves.state` returns it as `awayRequested`. `deathMoveSpent` (optional `true`, widened, LL1): `deathMoves.returnFromAway` sets it when the character comes back with every Hit Point marked, so no death move is due; `saveSheet` clears it whenever the saved sheet has `hp < hpMax`. Portraits: design art ids or Convex file storage uploads (old uploads deleted when replaced). |
| `frameTrackers` | `campaignId`, `key`, `data` (any), `updatedAt` | `by_campaign_key` | One row per campaign and frame tracker; each module in `convex/trackers/` validates `data` with zod (`src/lib/frames/trackers/*`) and filters it for players. Keys: `fiveBanners.state`, `colossus`, `ageOfUmbra`, `weredragon`, `andaluria`, `horizon`; character extras `character:<id>:{beastform,companion,motherboard,beastFeast,castleHigh}` and `beastFeast.cookbook` (`convex/characterExtras.ts`). `motherboard.corruption` (Motherboard's optional remnant Corruption Track, CB 295): `marks` (character id → 0–6, six boxes; a full track means the companion is lost), `remnant` (character ids whose companion is a remnant; widened with a default in RF4, so older rows read as none) and the latest rolls in `log`. Only a remnant that isn't lost rolls at the start of downtime (`convex/lib/restHooks.ts`). The owner or GM marks a remnant, the GM repairs 1d4 and the ranger replaces a lost companion (`convex/characterExtras.ts`). | Tracker blobs carry `schemaVersion` and are read through `readTracker(…, schema)` (bad or unknown data throws `TRACKER_CORRUPT`); `migrations/trackers:stampSchemaVersion` stamps existing rows.
| `codexEntryText` | `campaignId`, `entryId`, `pdesc`, `gmn` | `by_entry` | An entry's long texts, split from `codexEntries.data` (v2) so `codex.list` never reads them; `codex.entryText` returns `pdesc`+`gmn` to the GM and `pdesc` to players only while the entry is known. |
| `codexCounters` | `campaignId`, `entries`, `seeded` | `by_campaign` | Entry count for the 500-entry cap and whether the frame's starting NPCs were created (at campaign creation). |
| `codexEntries` | `campaignId`, `kind` (character/location), `data` (any; validated by `codexEntryDataSchema` in `src/lib/codex/schema.ts`: `name` ≤120, `role` ≤160, `known`, `pdesc` ≤8000, `gmn` ≤8000, `images` ≤8 `{storageId, shown}`, `cover`, `allegiance`, `allegianceShown`, `region`, `tokenId`), `createdAt`, `updatedAt` | `by_campaign_kind` | Characters & Locations (`convex/codex.ts`), ≤500 per campaign. GM-only writes. `codex.list` sends players only `known` entries with `name`, `pdesc`, the shown allegiance, the region, revealed images (URLs resolved only for those, keyed by opaque per-entry indexes instead of storage ids) and `tokenId` only when the linked World map token exists and isn't hidden; `role`, `gmn`, the true allegiance and hidden images never leave the server. The frame's starting characters are seeded once per campaign (`codex.seed`, idempotency key `codex:seed`). |
| `characterExtras` | `campaignId`, `characterId`, `extra` (beastform, companion, motherboard, beastFeast, skyshard…), `schemaVersion`, `data` (typed per extra), `updatedAt` | `by_character_extra`, `by_campaign` | Per-character frame extras. Legacy `character:<id>:<extra>` rows in `frameTrackers` are read as a fallback until `migrations/characterExtras:moveFromTrackers` has run. |

| `settings` | `ownerId`, `tableName`, `gmName`, `accent` | `by_owner` | One row per GM, created on first save. `accent` is one of the four palette colours. |
| `operations` | `scopeKey`, `idempotencyKey`, `kind`, `requestHash`, `result`, `campaignId?`, `createdBy`, `createdAt` | `by_scope_key`, `by_campaign` | Idempotency records (`convex/lib/operations.ts`). A replay with the same kind and normalised request returns `result`; anything else with the same key is `IDEMPOTENCY_MISMATCH`. Campaign create uses scope `owner:<id>`; Fear, countdown create and campaign time use `campaign:<id>`; countdown operations use `countdown:<id>`. With no event tables, these records are also the trail of applied changes. | Idempotency cache, not a trail: `internal.cleanup.expireOperations` deletes rows older than 7 days daily (`by_createdAt`); history lives in `history`.

## Indexes and query patterns

Every query on `files` and `grants` goes through an index; neither table is
scanned or filtered in memory.

| Table | Query | Index |
|---|---|---|
| `files` | Is this file claimed? (`isClaimed`); its owner for URL/delete (`ownFileUrl`, `deleteOwnFile`); migration de-duplication | `by_storage` [storageId] |
| `files` | A codex entry's or character's files, on entry/character deletion (`deleteFilesOf`) | `by_ref` [kind, refId] |
| `files` | A campaign's files (per campaign or per kind): listing, backup export, campaign cleanup | `by_campaign_kind` [campaignId, kind] (its prefix serves per-campaign) |
| `files` | A user's uploads: account deletion, per-user quotas | `by_uploader` [uploadedBy] |
| `grants` | `permissionFor`: one point lookup per principal (the user, then each campaign they run or belong to) and per target (the resource, then its campaign); skipped when the role already gives the needed permission | `by_resource_principal` [resourceType, resourceId, principalKind, principalId] |
| `grants` | One grant per (resource, principal) (`upsertGrant`); who has access to a resource and cleanup on resource deletion (prefix) | `by_resource_principal` |
| `grants` | What is shared with me; cleanup when a user or campaign is deleted | `by_principal_type` [principalKind, principalId, resourceType] |
| `grants` | Revoking the grants a user created; account deletion | `by_creator` [createdBy] |

The user's campaigns for `permissionFor` come from `campaigns.by_owner_deletedAt_lastOpened`
(prefix on `ownerId`) and `campaignMembers.by_user`. List queries compute the
permission once per request (`characters.listByCampaign` uses the campaign
permission plus "your own character"; `codex.list` uses the campaign
permission), not per row.

Convex Auth's `authTables` are included unchanged.


## Retention jobs (`convex/crons.ts`, `convex/cleanup.ts`)

- Daily: expire `operations` older than 7 days; delete uploads older than 2 hours that no `files` row (or deprecated upload table) claims.
- Not scheduled: campaign purge (see `campaigns`), waiting for a GM "Delete permanently" action.
