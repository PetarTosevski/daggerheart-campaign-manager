# TASK-RT2: GM website UI for rest ticks (card, create forms, rest panel)

Status: Review. Plan: `.omc/plans/rest-ticks.yaml`, tracer RT2 (wave 2). Bead: dcm-674k. Builds on RT1's API (`docs/tasks/TASK-RT1.md`).

## What the GM gets

- **`RestTickControl`** (`src/app/(gm)/campaigns/[campaignId]/countdowns/rest-ticks.tsx`): one rest setting as a fieldset named "On long rest" / "On short rest": Off / On (pressed buttons), "Ticks" (A fixed number, PCs who rested, A die, A die + PCs who rested), "Number (1 to 20)" for a fixed amount, "Die" (d4..d20) for the die kinds, and "How": Automatic / Reminder. Native selects and a number field, 44 px controls (`min-h-11`, BrandButton md). Switching on starts at 1 tick, Automatic; switching kind keeps the number or the die size (a die starts on d6). `live` (create forms) reports every valid keystroke of the number; on the card the number is sent once when the field is left or Enter is pressed (a draft only while typing; no props copied into state).
- **Card** (`card.tsx`): GM only (`armed !== null`), not cancelled: a one-line summary ("Long rest: d6 + PCs who rested, Reminder · Short rest: Off") and a "Rest ticks" disclosure (`aria-label "Rest ticks of <name>"`) holding both controls. Each change is one `countdowns.setRestTick` call (one rest kind) through `useKeyed`, with an optimistic update of `listByCampaign` (`withRestTick`: the field, and on long-term the transition `armed` / `restMode` derived from the long-rest setting, as the server derives them). Armed stays for every non-long-term type with its existing copy; long-term shows no Armed switch (Q3).
- **Long-term track** (`track.tsx`): the old "On long rest: Automatic / Reminder" switch (`RestModeSwitch`, `countdownTracks.setRestMode`) is gone; the website no longer calls `setRestMode`. A track with no rest setting says "Rests leave it alone. Set it to tick on long rests under Rest ticks."
- **Chase card** (`chase.tsx`): one Rest ticks disclosure per pair, on an open row; the server writes both rows, the optimistic update patches both (`pairIds` and `chase.partnerId`).
- **New countdown** (`new-dialog.tsx`): a "Rests" section with both controls, sent as `onLongRest` / `onShortRest` (omitted when Off). Standard / progress / consequence start Off; long-term starts "On long rest: 1, Automatic" (CB p.164, the old default `armed: true`), kept separately so switching type and back does not lose either. Long-term hides the Armed box and sends `armed: false` (no legacy `restMode` sent any more).
- **New chase** (`chase.tsx`): the same "Rests" section, both Off, shared by both countdowns.
- **Rest panel** (`src/components/party/rest/long-term.tsx`): heading "Countdowns"; the latest rest's lines and reminders for any countdown type and either rest kind (whatever `afterRest` returns), each reminder "Tick <name>? <amount> (<roll text>)" (just the amount for a fixed setting) with one "Tick −<amount>" button (`aria-label "Tick <name>"`) calling `tickOnRest`; optimistic: the reminder becomes a line and the card (both chase rows) moves by the stored amount through `tickCountdown`. The `data-testid="rest-long-term"` and the export name `LongTermAfterRest` stay (the launcher, `countdowns-flow.spec.ts` and `visual/CD-K4.spec.ts` use them).

## Outside RT2's owns (for the orchestrator)

1. `src/components/party/rest/launcher.tsx` line 136 only mounts the panel after a **finished long rest** (`last.kind === "long" && last.status === "finished"`). For short-rest and interrupted-long-rest reminders to show on the website the condition must become `isGm && last !== null ? <LongTermAfterRest campaignId={campaignId} /> : null` (`afterRest` already returns null when nothing applies, and the panel renders nothing then). Without it, a short-rest Reminder is stored but not offered on the website (the e2e spec does not depend on it: its short rest is Automatic).
2. `tests/e2e/countdowns-flow.spec.ts` line 108 expects the removed long-term checkbox "Tick on every long rest"; replace it with `await expect(dialog.getByRole("group", { name: "On long rest" }).getByRole("button", { name: "On", exact: true })).toHaveAttribute("aria-pressed", "true");`.
